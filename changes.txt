Изменения в проекте (дата: 2025-12-17)
====================================

1. main.py
----------
- Вместо статической матрицы из `matrix_task/distane_matrix.py` теперь используется загрузка матрицы расстояний из TSPLIB-файла через функцию `load_tsplib_instance` из `matrix_task/tsp_task.py`.
- Добавлена глобальная переменная `DISTANCE_MATRIX, OPTIMAL_VALUE = load_tsplib_instance("matrix_task/st70.tsp")`.
- В конструктор `ABCAlgorithm` передаётся `OPTIMAL_VALUE`, чтобы использовать его в расчёте разницы с оптимумом.
- В вывод результатов добавлен вывод оптимального значения из TSPLIB (если оно известно).

2. matrix_task/tsp_task.py
--------------------------
- Функция `load_tsplib_instance(filename)` оформлена как чистая функция модуля: она загружает TSP-задачу через `tsplib95`, строит матрицу расстояний (`numpy.ndarray`) и возвращает её вместе с `optimal_value` (если он есть).
- Если `optimal_value` в задаче не задан, для `st70.tsp` оптимум принудительно устанавливается в 675.
- Пример использования и печать матрицы/оптимума вынесены под `if __name__ == "__main__":`, чтобы при импорте из `main.py` не выполнялся лишний код.

3. bees/employedBee.py
----------------------
- Серьёзно расширена логика генерации новых решений в методе `generate_new_solution`:
  - Добавлен выбор между разными операторами:
    - OX-кроссовер (Order Crossover) с партнёрским решением (`_ox_crossover`).
    - 2-opt шаг (`_two_opt_move`) как локальное улучшение тура.
    - Double-bridge мутация (`_double_bridge_move`) как сильная перестройка маршрута.
  - Если `trial` у пчелы больше 20, используется double-bridge мутация для выхода из локального минимума.

4. bees/onLookerBee.py
----------------------
- Расширена логика мутаций в `_generate_new_solution` для пчёл-наблюдателей:
  - Ранее использовались только операции inversion/swap/shift.
  - Теперь добавлены:
    - 2-opt шаг (`_two_opt_move`) как дополнительный локальный оператор.
    - Double-bridge мутация (`_double_bridge_move`) для агрессивной перестройки тура.
  - Если `trial` у наблюдателя больше 20, применяется double-bridge мутация, иначе случайно выбирается одна из более мягких мутаций (inversion, swap, shift, two_opt).


5. ABC.py
---------
- В конструктор `ABCAlgorithm` добавлены параметры:
  - `distance_matrix` — матрица расстояний для использования в эвристиках инициализации (опционально).
  - `local_search_interval` — как часто (в итерациях) запускать локальный поиск вокруг текущего лучшего решения.
  - `local_search_iterations` — сколько 2-opt шагов выполнять в локальном поиске.
  - `elitism_rate` — доля худших рабочих пчёл, которые периодически заменяются копией лучшего решения (элитизм).
  - `heuristic_init_ratio` — доля решений в начальной популяции, которые генерируются эвристиками (по умолчанию 0.7, т.е. 70%).
- В цикле `run_algorithm` добавлены:
  - Вызов `_apply_elitism()` — замена части худших рабочих пчёл текущим лучшим маршрутом.
  - Вызов `_local_2opt_search()` — локальный жадный поиск 2-opt вокруг текущего лучшего решения.
- Метод `_initialize_population` полностью переработан:
  - РАНЬШЕ: все решения генерировались полностью случайно через `random.sample()`.
  - ТЕПЕРЬ: используется смешанная стратегия инициализации:
    - Вычисляется количество эвристических решений: `num_heuristic = int(self.num_employed_bees * self.heuristic_init_ratio)` (по умолчанию 70%).
    - Если `distance_matrix` передан в конструктор:
      - Эвристические решения генерируются по очереди:
        * Каждое третье решение (i % 3 == 0): `_nearest_neighbor_init()` — ближайший сосед со стартом с города 0.
        * Каждое второе решение (i % 3 == 1): `_greedy_init()` — жадная эвристика.
        * Остальные (i % 3 == 2): `_nearest_neighbor_init(random_start=True)` — ближайший сосед со случайным стартом.
      - Остальные решения (30% по умолчанию) генерируются случайно для разнообразия популяции.
    - Если `distance_matrix` не передан, все решения генерируются случайно (как раньше).
- Добавлены новые методы:
  - `_two_opt_move` — один шаг 2-opt над маршрутом.
  - `_local_2opt_search` — многократное применение 2-opt к текущему лучшему решению с обновлением части популяции, если найдено улучшение.
  - `_apply_elitism` — простая стратегия элитизма, распространяющая лучшее решение на худших пчёл.
  - `_nearest_neighbor_init` — эвристика ближайшего соседа для построения начального тура (всегда идём к ближайшему непосещённому городу).
  - `_greedy_init` — упрощённая жадная эвристика: строим тур, выбирая ближайший город к любому концу уже построенной части тура.
