ИНТЕГРАЦИЯ ILS В ABC ДЛЯ TSP
=============================

СОЗДАННЫЕ ФАЙЛЫ:
- tsp_optimizations.py - модуль с ILS-компонентами и мутациями
- abc_ils_hybrid.py - гибридный ABC+ILS класс с параллельностью
- main_abc_ils.py - запуск алгоритма

ЧТО ДОБАВЛЕНО ИЗ ILS:

1. 2-opt локальный поиск (tsp_optimizations.py)
   - local_search_2opt() - эффективный поиск до локального оптимума
   - Используется в _local_2opt_search_global() каждые local_search_interval итераций

2. Эвристики инициализации (tsp_optimizations.py)
   - nearest_neighbor_init() - ближайший сосед
   - greedy_init() - жадное построение
   - Используются в _initialize_population() с параметром heuristic_init_ratio

3. Операторы возмущения (tsp_optimizations.py)
   - double_bridge_perturbation() - сильное возмущение через 4 разреза
   - perturbation_2opt_random() - случайные 2-opt обмены
   - Используются в employed_bee_phase() и scout_bee_phase()

4. Дополнительные мутации (tsp_optimizations.py)
   - swap_mutation() - обмен двух городов
   - insertion_mutation() - вставка города
   - inversion_mutation() - инверсия подтура
   - scramble_mutation() - перемешивание сегмента
   - or_opt_mutation() - перемещение сегмента (OR-opt)
   - apply_random_mutation() - применение случайной мутации из набора
   - Используются в employed_bee_phase() и onlooker_bee_phase() при улучшении

5. Numpy-оптимизация
   - distance_matrix хранится как np.float64
   - Быстрая индексация dist[i, j]

6. Параллельность (abc_ils_hybrid.py)
   - ProcessPoolExecutor для параллельной генерации решений
   - Параллельное вычисление фитнеса при инициализации
   - Параметр num_workers для контроля количества процессов

ИЗМЕНЕНИЯ В abc_ils_hybrid.py:
- _initialize_population(): смесь NN/greedy/случайных туров, параллельная генерация
  * Увеличена доля эвристических решений до минимум 90% (больше nearest neighbor)
- employed_bee_phase(): возмущение при trial > limit//3, умеренные мутации (ОПТИМИЗИРОВАНО)
  * Мутации при улучшении: 1 с вероятностью 50% (для ускорения)
  * Мутации при возмущении: 1-2 (оптимизировано)
  * Убраны лишние мутации без улучшения
- onlooker_bee_phase(): умеренные мутации (ОПТИМИЗИРОВАНО)
  * Мутации при улучшении: 1 с вероятностью 50%
  * Убраны мутации без улучшения
- scout_bee_phase(): возмущение с вероятностью 0.8, добавлены мутации
  * Мутации при возмущении: 1 (оптимизировано)
- _local_2opt_search_global(): периодический 2-opt над лучшим решением
  * Увеличена доля элиты до 25% (было 20%)
  * Добавлены мутации при распространении элиты
- _elitist_update_from_onlookers(): элитизм после onlooker phase
- Добавлен параметр num_workers для параллельности
  * Параллельность автоматически отключается для задач < 200 городов (overhead больше выгоды)
- Добавлена ЭФФЕКТИВНАЯ GPU поддержка через CuPy (RTX 2070)
  * Параметр use_gpu для включения/выключения GPU
  * Матрица расстояний переносится на GPU
  * GPU используется для вычисления длин туров (для задач > 50 городов)
  * Пакетное вычисление длин туров на GPU в onlooker_bee_phase (очень эффективно)
  * Методы _calculate_tour_length_gpu() и _calculate_tour_lengths_batch_gpu() для GPU вычислений
- ОПТИМИЗАЦИЯ ПРОИЗВОДИТЕЛЬНОСТИ:
  * Уменьшено количество мутаций (1-2 вместо 2-5) для ускорения
  * Убраны лишние мутации без улучшения
  * Параллельность только для больших задач (>200 городов)
  * Оптимизированы параметры по умолчанию

- УЛУЧШЕНИЯ ДЛЯ ЛУЧШЕГО РЕШЕНИЯ (для задач 70+ городов):
  * Интенсивный локальный поиск в конце алгоритма (последние 20% итераций)
  * Применение 2-opt к топ-5 решениям в популяции для финальной дооптимизации
  * Быстрый 2-opt к 30% эвристических решений при инициализации
  * Улучшенная стратегия возмущения: пробуем несколько вариантов и выбираем лучший
  * Увеличена доля элиты до 33% (было 25%)
  * Увеличена частота 2-opt (каждые 20 итераций вместо 30)
  * Увеличены параметры: популяция (100/150), patience (400), итерации (3000)
  * Более агрессивное возмущение в employed_bee_phase (пробуем 2 варианта)
  * Более агрессивное возмущение в scout_bee_phase (пробуем 3 варианта)
  
- КРИТИЧЕСКИЕ УЛУЧШЕНИЯ ДЛЯ ПРЕОДОЛЕНИЯ ЗАСТРЕВАНИЯ:
  * Добавлен 3-opt локальный поиск (local_search_3opt) - более мощный чем 2-opt
  * 3-opt применяется к лучшему решению каждые 50 итераций
  * Добавлен ограниченный 2-opt (local_search_2opt_limited) для быстрого улучшения
  * Адаптивная частота локального поиска - в 3 раза чаще если нет улучшений >50 итераций
  * Адаптивное возмущение - более агрессивное если нет улучшений >100 итераций
  * Интенсивный поиск начинается с 70% итераций (было 80%)
  * Применение 2-opt к топ-10 решениям (было топ-5) в интенсивном поиске
  * Счетчик no_improvement_count для адаптации параметров
